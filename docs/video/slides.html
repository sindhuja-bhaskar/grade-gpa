Grade/GPA Planner

Personal Academic Performance & GPA Planning System — a cloud-based web application for tracking assessments, calculating GPA and CGPA, and planning the marks a target requires.

Faculty: Dr. P. Anandan

The problem

A mark that has not been released is not a zero

Spreadsheets and generic calculators average whatever is in the column. An unreleased FAT becomes a zero, and the student sees a failing projection that answers a question nobody asked.

The system keeps four things distinct: marks earned, assessments not yet available, planning targets, and official grades — and never presents one as another.

Architecture

Three tiers, one deployment

          Student (browser)
                 |  HTTPS
   +-------------v--------------------------------+
   |  NEXT.JS DEPLOYMENT                          |
   |    Presentation   server + client components |
   |    Application    /api routes, Server Actions|
   |    Services       ownership, persistence     |
   |    CALCULATION ENGINE  pure, unit-tested     |
   +-------------+--------------------------------+
                 |  Prisma + pooled pg adapter
        +--------v---------+
        |   PostgreSQL     |  cloud-hosted
        +------------------+

The tier boundary is enforced in code: engine and data access are server-only modules that cannot be imported into the browser bundle.

Implementation

Rules in one place, tested on their own

  • Calculation engine — pure TypeScript modules, no React, no Prisma; 64 unit tests covering the specification's worked examples and every grade boundary
  • Configuration, not constants — weightages, grade bands and thresholds live outside the calculation functions
  • REST API — endpoints under /api with OpenAPI 3.0 documentation generated from the same validation schemas the handlers use
  • Authentication — Auth.js with server-side session records; every request re-checks record ownership

Cloud deployment

One application, a managed database, no secrets in code

Application

Cloud-hosted Next.js deployment serving both the interface and the API over HTTPS.

Database

Managed PostgreSQL reached through a connection pooler — serverless functions would otherwise exhaust a free-tier connection limit.

Configuration

Database URL and session signing key supplied as environment variables; migrations applied with prisma migrate deploy.

Demonstration

The working application

Official CGPA from completed courses · a semester with nothing completed reads "not yet available" · ongoing subjects show a status, never a grade · required marks for a target · a subject completing only when every component is recorded.

In summary

Every rule enforced in code, not just in the interface

  • An unavailable assessment counts towards nothing — it is never a zero
  • An ongoing subject has no grade to show
  • A GPA with nothing completed is "not yet available", never 0.00
  • A required mark is a requirement — including when the answer is that the target can no longer be reached
